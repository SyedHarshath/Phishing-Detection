# Data and privacy

The prediction database stores full submitted URLs. URL paths, query parameters, and fragments can contain credentials, session tokens, personal data, or private identifiers. The extension now requires a first-use affirmative consent before sending navigation or manual scans; the disclosure says full URLs are transmitted/stored and that authorized reviewers may inspect URLs submitted with feedback. The popup can stop future scans, but does not delete server-side records. `/predictions` is disabled unless `PHISHGUARD_PREDICTIONS_TOKEN` is set and requires the matching `X-PhishGuard-Admin-Token` header. Responses omit URLs by default; an authenticated caller must request `?include_urls=true` to receive them. This is a shared-secret gate, not user-level authorization: configure a high-entropy secret, use HTTPS through a trusted TLS terminator for remote access, and restrict access to that terminator and the database filesystem. Loopback binding in Compose is defense in depth, not the access control. The database itself is not encrypted by the application. No retention/deletion policy is implemented. Do not send collected URLs to external services.

Feedback is an unverified user assertion and remains pending review after it is recorded. It cannot enter an approved training batch until the reviewer CLI records an explicit verification with reviewer and provenance. Approved batch export checks eligibility and writes a fingerprinted batch; it does not start training or clear the separate dataset provenance and DVC gates. Dataset source files are untrusted inputs; the strict validator never visits URLs and reports content fingerprints without rewriting source data.

The prediction API sanitizes model-load and inference failures returned by `/health`, `/ready`, `/model-info`, and `/predict`; detailed local artifact paths are not part of those responses. `/live` reports process liveness, while `/ready` returns 503 if the model cannot load. `/predictions` requires the shared token described above, while stored database URLs remain sensitive and are not redacted at rest. Treat database and batch files as sensitive.
