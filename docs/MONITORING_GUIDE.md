# Monitoring guide

`python -m mlops.monitoring.monitor` reads the configured prediction database (`DATABASE_URL` PostgreSQL when set, otherwise the configured SQLite file), prints aggregate prediction counts, confidence, URL length, and feedback agreement, writes `mlops/monitoring/monitoring_run.json`, and attempts to log to MLflow. It logs only the database backend name, never the connection URL. Feedback agreement is only agreement with unverified user claims; it is not an accuracy estimate. The command may start a local MLflow server through current configuration. `python -m mlops.monitoring.drift` and `python -m mlops.monitoring.dashboard_data` use the same backend selection; the dashboard masks URLs. The read-only disagreement extractor still accepts an explicit SQLite source file for offline review artifacts.

No alert thresholds, drift windows, calibration checks, or scheduled monitoring are configured. Treat outputs as descriptive aggregates, not evidence of model quality. Protect the database and generated reports because raw URLs may be present in the database. Do not publish them without URL redaction/access controls.
